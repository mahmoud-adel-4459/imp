1. دورة حياة الطلب بالتفصيل (Request Lifecycle)

ماذا يحدث في السيرفر منذ اللحظة التي يضغط فيها المستخدم "إرسال" وحتى عودة استجابة JSON؟

01

نقطة الدخول (Entry Point)

يصل الطلب إلى public/index.php. يتم تحميل الـ Autoloader الخاص بـ Composer ثم استدعاء ملف التهيئة bootstrap/app.php لإنشاء كائن التطبيق الأساسي $app.

02

الـ Kernel ومصفوفة الـ Middlewares

يمر الطلب عبر مصفوفة Middlewares مثل CORS، فحص الصيانة، وإزالة الفراغات، وتحديد معدل الطلبات (Rate Limiting) لحماية السيرفر من هجمات DDoS.

HTTP Pipeline
03

التوجيه والمصادقة (Routing & Sanctum)

يقوم الـ Router بمطابقة الـ URL المطلوب مع المسارات المعرفة في routes/api.php أو web.php. يقوم Sanctum Guard بالتحقق من Bearer Token وتعيين المستخدم الحالي auth()->user().

04

التحقق من المدخلات (FormRequest)

قبل تشغيل الكنترولر، تقوم كلاسات FormRequest بالتحقق الدقيق من الحقول والأنواع. إذا كانت هناك أخطاء يتم إيقاف الطلب وإرجاع 422 Unprocessable Content فوراً.

Validation Rules
05

الكنترولر وطبقة الخدمات (Service Layer)

الكنترولر يستقبل المدخلات المعتمدة ويوجهها إلى الـ Service المختص (مثل OrderService) لمعالجة العمليات وحفظ وتحديث البيانات عبر Eloquent ORM في المعاملات (DB Transactions).

06

تنسيق وإرسال الاستجابة (API Resource)

يتم تغليف النماذج في JsonResource لتوحيد هيكل الـ JSON للموبايل، وتشفير أو إخفاء أي بيانات حساسة، ثم إرسال HTTP Response بحالة مناسبة (200, 201, 404...).

القلب النابض للارافيل

2. الحاوية الخدمية وحقن التبعيات (Service Container & DI)

المحرك المسؤول عن إدارة الكائنات وبنائها تلقائياً عند الحاجة دون كتابة new Class() يدوياً.

حقن التبعيات التلقائي (Automatic Auto-Wiring)

عندما تطلب كلاس داخل Constructor الكنترولر، يقرأ محرك الـ Reflection في لارافيل النوع المطلوب وينشئه ويمرره تلقائياً:

namespace App\Http\Controllers\Api;

use App\Services\OrderService;
use App\Http\Requests\StoreOrderRequest;

class OrderController extends Controller {
  // يتم حقن كائن OrderService تلقائياً عبر Container
  public function __construct(
    protected OrderService $orderService
  ) {}

  public function store(StoreOrderRequest $request) {
    $order = $this->orderService->createOrder($request->validated());
    return new OrderResource($order);
  }
}

أنواع التسجيل في الـ Container (Bindings)

  • Singleton Binding

    يتم إنشاء نسخة واحدة فقط من الكلاس ومشاركتها طوال دورة حياة الطلب (مثل KashierClient و FirebaseService).

  • Scoped Binding

    يتم إنشاء نسخة جديدة لكل طلب HTTP وإتلافها بعد انتهاء الطلب.

  • Interface to Implementation

    ربط Interface بكلاس معين، مما يتيح لك تغيير مزود خدمة الدفع أو الـ SMS بسهولة في سطر واحد داخل AppServiceProvider.

التفاعل مع قاعدة البيانات

3. محرك النماذج الفصيح (Eloquent ORM & Query Builder)

كيف يربط Eloquent جداول قاعدة البيانات بكائنات برمجية قوية مع تجنب بطء الاستعلامات.

أنواع العلاقات المطبقة في TechShop

  • One to Many (hasMany / belongsTo)

    الـ Vendor يمتلك فروعاً متعددة branches()، والـ Order يمتلك عدة vendorOrders().

  • Many to Many (belongsToMany)

    الـ Product يرتبط بعدة Category عبر جدول وسيط product_categories.

  • Polymorphic Relations (morphMany)

    التقييمات ratings() والشكاوى reports() يمكن أن ترتبط بمنتج أو بتاجر أو بمندوب باستخدام نفس الجدول.

الحماية من مشكلة الاستعلامات الكارثية (N+1 Problem)

استخدام الـ Eager Loading مع with() يقلل عدد الاستعلامات من 101 استعلام إلى استعلامين فقط:

// ❌ طريقة بطيئة (N+1 Queries):
$orders = Order::all(); // 1 query
foreach ($orders as $order) {
  $vendor = $order->vendorOrders; // 1 query per order!
}

// طريقة سريعة ومثالية (Eager Loading):
$orders = Order::with(['vendorOrders.items', 'user', 'address'])->get();
السرعة واللحظية

4. البث اللحظي والطوابير (Reverb WebSockets & Queues)

كيف يتعامل النظام مع آلاف الأحداث المتزامنة دون إبطاء تجربة العميل.

Laravel Reverb WebSockets

خادم WebSockets فائق السرعة مدمج مع Laravel 12، يفتح قناة اتصال ثنائية الاتجاه مع تطبيقات الموبايل لبث تغير حالات الطلبات وتتبع المناديب بالـ GPS لحظة بلحظة.

php artisan reverb:start

Queue Workers (معالجة الخلفية)

ترحيل العمليات الثقيلة مثل إرسال إشعارات FCM، توليد فواتير PDF، وتصدير التقارير لـ Excel إلى طوابير Redis أو Database لضمان سرعة استجابة الـ API في أجزاء من الثانية.

php artisan queue:work

Task Scheduler (الكرون التلقائي)

إدارة كافة المهام الدورية (فحص الاشتراكات المنتهية، تفعيل الخطط المجدولة، إغلاق الشيفتات المتأخرة) في ملف routes/console.php وتشغيلها آلياً كل دقيقة.

php artisan schedule:run
معايير الإنتاج الاحترافية

5. أفضل الممارسات البرمجية لضمان كود احترافي (Best Practices)

القواعد الذهبية المطبقة في هذا المشروع لضمان استقرار وسرعة وأمان النظام.

1. Single Responsibility: الكنترولر للتوجيه فقط، والـ Service للعمليات، والـ Model للعلاقات والـ Scopes.
2. Strategy Pattern: فصل منطق المنتجات البسيطة عن المتغيرة لسهولة إضافة أنواع جديدة مستقبلاً.
3. Idempotent Operations: حماية الـ Webhooks والمعاملات المالية من التكرار عبر PaymentWebhookEvent.
4. Database Indexing: فهرسة حقول الـ Foreign Keys والـ Status لتقليل زمن الاستعلامات المعقدة.
5. FormRequests over Controller Validation: تجريد قواعد التحقق في كلاسات منفصلة لسهولة الاختبار وإعادة الاستخدام.
6. Automated Testing: كتابة Feature Tests لاختبار دورة الطلبات والمدفوعات آلياً مع كل تحديث.
